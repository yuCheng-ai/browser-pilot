# 安全边界

## 原则

- 本地优先：浏览器状态、任务证据和登录态默认只保存在本机。
- 最小权限：任务只获取完成当前目标所需的页面、profile 和工具能力。
- 高风险前置拦截：不可逆动作在执行前识别和判定。
- 全程可追踪：动作、风险决策、确认记录和结果都进入任务运行记录。

## 风险动作

| 风险级别 | 示例 | 默认处理 |
| --- | --- | --- |
| 高 | 支付、下单、转账、删除、发布、审批通过、批量提交 | 阻止自动直通，要求显式确认或策略放行。 |
| 中 | 登录、上传文件、下载敏感报表、导出数据、修改配置 | 记录上下文，按策略要求确认。 |
| 低 | 打开页面、读取公开文本、滚动、截图、非提交型筛选 | 允许执行并保留证据。 |

## 登录态处理

- 登录态数据放在 `storage/profiles`，不进入源码仓库。
- 每个任务运行记录使用了哪个 profile，但不把 cookie 明文写入报告。
- profile 失效、站点重新验证或遇到验证码时，任务应暂停并暴露原因。
- 不把用户密码作为默认任务参数持久化。

## 数据处理

- 截图和 DOM 快照可能包含敏感数据，应按任务用途决定保留周期。
- 报告默认引用证据，不应无差别复制页面中的隐私字段。
- 提取器应允许字段脱敏、白名单输出和导出审计。
- 模型适配层应明确哪些页面内容会发送给远端模型。

## 安全守卫职责

1. 在动作执行前识别动作类型、目标页面、目标元素和可能后果。
2. 对命中策略的动作返回 `allow`、`confirm`、`block` 或 `escalate`。
3. 把策略判定和用户确认写入 task run。
4. 对敏感字段、文件上传和跨站数据流建立独立检查点。

## 首版红线

- 不自动绕过验证码、人机验证或站点反自动化策略。
- 不在未知后果下默认点击支付、删除、发布和最终提交按钮。
- 不把 profile、cookie、截图和任务运行数据提交到版本库。
- 不把远端模型调用伪装成本地执行，调用边界必须可见。
